# Pull request 12: make SonarQube analysis exact and authoritative

## Summary

- Remove the static semantic scanner version and require the exact checked-out
  commit SHA for every analysis.
- Check out the immutable pull-request head rather than a synthetic merge.
- Validate the shared `Previous version` project policy after analysis.
- Reject unresolved new findings on pull requests and every unresolved finding
  on authoritative `main` analyses.

`api/new_code_periods/show`. Its project settings endpoint exposes the active
policy as `sonar.leak.period=previous_version` and
`sonar.leak.period.type=previous_version`, so CI validates those two values
directly, matching the other container-family repositories.
